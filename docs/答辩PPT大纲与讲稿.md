## 二、3 分钟逐字讲稿（约 620 字）

**【0:00-0:25 背景与选题】P2**
各位老师好，我的课程设计题目是《基于机器学习的工业产品质量智能检测系统》。制造质检普遍依赖人工目检，存在易疲劳、易漏检的问题；同时缺陷样本稀少，传统规则难以覆盖。我选用公开工业数据集 KolektorSDD——它是换向器表面的 399 张灰度图像，其中仅 52 张含缺陷，缺陷又是几像素的细暗条，类不平衡接近 1 比 7，非常适合检验一个质检系统到底有没有用。

**【0:25-1:00 方案与数据】P3-P4**
整体方案是：图像先经预处理，再并行送入两条 AI 路线——深度学习 CNN 与"传统特征加随机森林"，最后做双证据融合，构成完整 B/S 系统。
数据方面，原始图是宽 500、高约 1250 的细长图，我采用等比缩放加居中填充到 384 乘 384，保证几何不失真；并按缺陷标签分层划分成训练、验证、测试 279 比 60 比 60。
这里我想特别说明两处靠审计发现并修复的问题：一是早期预处理把标注掩码误当图像入库，导致数据集翻倍污染；二是掩码文件保存时丢了工件前缀而被覆盖。这两个例子正是 vibe coding 中"人工审查 AI 代码"的价值。

**【1:00-1:55 两条 AI 路线】P5-P6**
算法上，深度学习路线我用自研的轻量 SmallCNN，仅 24 万参数，端到端学习缺陷特征；针对不平衡做了类别加权，并实验发现：样本很少时过度数据增强反而欠拟合，因此只保留水平翻转。
第二条路线是传统模式识别——我把图像沿高切成 8 条带，逐带提取 LBP 纹理、梯度和统计特征，共约 312 维，再用随机森林判别。对比发现：CNN 灵敏、漏检少，召回 0.875；传统 RF 特异、误报少，精确率达 1.0。
所以我设计成双证据融合：两路同判缺陷为 NG，分歧则转入人工复检，两路正常才放行——既守住漏检，又降低误报，符合"宁多检、不漏放"的质检逻辑。

**【1:55-2:40 系统与演示】P7**
系统是完整 B/S 架构：前端支持拖拽上传、实时展示双路概率、缺陷位置和判定徽章，并配 ECharts 质检统计看板；后端用 Flask 提供服务，SQLite 存储每次检测与人工复检记录，形成"检测—裁决—复检—留档"的业务闭环。现场已实测：缺陷图判 NG、正常图判 OK，复检后统计同步联动，单次检测低于 3 秒。

**【2:40-3:00 测试与总结】P8-P9**
测试方面，我建立了 14 项 pytest 自动化测试，覆盖数据、几何、特征、推理与 API 全流程并全部通过。整套系统也同步沉淀了 git 提交记录与过程档案。
展望上，后续可引入无监督异常检测与像素级分割，进一步提升对极端微小缺陷的检出能力。
我的汇报到此结束，谢谢各位老师！

## 三、问答预案（随机代码段讲解准备）
1. **问：`service.py` 的裁决函数为什么是这三态？** → 讲 CNN 高灵敏+RF 高特异互补；分歧=不确定性高，交给人工是质检场景的正确取舍；代码简单 `if cnn&&ml→NG ...`。
2. **问：特征 312 维怎么来的？** → 全局统计 4 + 4×4 分块均值方差 32 + LBP 直方图 256 + 梯度方向 18+1 + 边缘密度 1 = 312。
3. **问：为什么切 8 条带而不是直接整图分类？** → 缺陷整图占比极小，全局统计学不到；切带后缺陷在带内占比上升，还能顺带给出定位（ml_band）。
4. **问：为什么过度增强反而更差？** → 训练仅 279 张，增强增大学习难度导致欠拟合；A/B 实测验证 BAcc 0.75→0.5。
5. **问：384 输入为什么是等比+pad？** → 直接 resize 到方形会把细长缺陷压扁 2.5 倍、几何失真；pad 保持长宽比，训练/推理同分布。
6. **问：SmallCNN 怎么设计的？** → 输入单通道 384；4 组卷积（核3、步2）+BN+ReLU，最后全局平均池化接 2 分类头，约 24 万参数，CPU 也可跑。
7. **问：双证据 vs 简单阈值哪个好？** → 单模型阈值难以同时压低漏检与误报；融合让两路相互校验，分歧显式走人工，可用性更好。
8. **问：数据为什么不入 git？** → 原始/加工图体积大且可由 `scripts/preprocess.py` 精确再生，故只提交脚本、标注与划分，仓库更轻量可复现。
